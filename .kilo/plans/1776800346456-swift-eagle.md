# Plan: Congress Politician & Institution Detail Side Panel

## Overview

When a user clicks on a congress politician's name in the Congress tab or an institution/filing row in the Institutions tab of the Portfolio Tracker panel, instead of showing holdings inline, open the right-side `EntityDetailPanel` with a clean profile page featuring:

- Hero image of the person/institution
- Profile header with badges and summary metrics
- A tab system modeled on the reference layouts you shared
- Holdings/trades breakdown by quarter
- PnL/performance charting
- Historical detail and filing/disclosure sources

### Target Tab Model

Both institution and politician detail panels should use the same top-level tab language as the reference screenshots, adapted to the data we actually have:

- **Top Holdings**
- **Largest Trades**
- **AI Insights**
- **Portfolio Structure**
- **Performance History**
- **Filings / Disclosures**

This keeps the right panel visually aligned with the examples while allowing the content inside each tab to differ slightly for institutions vs politicians.

### Institution-Only Extra Tabs

Institutions should also support an additional **AUM** tab based on the latest screenshot reference.

- **AUM**

This tab is institution-specific and should not appear for politicians unless we later add a meaningful equivalent data model.

### 4. NEW: `src/components/entity-detail/renderers/congress-politician.ts`

New `CongressPoliticianRenderer` class implementing `EntityRenderer`:

**Data interface:**
```ts
interface CongressPoliticianData {
  name: string;
  party: string;
  chamber: 'House' | 'Senate';
  district?: string;
  state?: string;
}
```

**Enriched data interface:**
```ts
interface CongressPoliticianEnriched {
  name: string;
  party: string;
  chamber: 'House' | 'Senate';
  district?: string;
  state?: string;
  trades: CongressTrade[];
  totalBuys: number;
  totalSells: number;
  totalVolume: string; // estimated
  quarterlyBreakdown: QuarterlyBreakdown[];
  topTickers: TickerHolding[];
  wikiSummary?: string;
  wikiUrl?: string;
}

interface QuarterlyBreakdown {
  quarter: string; // "2024 Q1"
  buys: number;
  sells: number;
  topTicker: string;
}

interface TickerHolding {
  ticker: string;
  name: string;
  buyCount: number;
  sellCount: number;
}
```

**`renderSkeleton()`**: Header with name, party badge (R red / D blue), chamber badge, skeleton loading placeholders.

**`enrich()`**: 
- Fetch all congress trades via `fetchCongressTrades()`, filter by `name`
- Aggregate quarterly breakdown
- Compute top tickers
- Fetch Wikipedia summary for the politician (via hero image system, which is already called in the panel's `show()` method)

**`renderEnriched()`**: Render tabs: **Top Holdings** | **Largest Trades** | **AI Insights** | **Portfolio Structure** | **Performance History** | **AUM** | **Filings / Disclosures**

- **Top Holdings tab**: Aggregated current positions estimated from net trades per ticker, ranked list/table, concentration stats, top names, percentage bars
- **Largest Trades tab**: Biggest buy/sell activity, grouped sections for top buys and top sells, sortable detailed transaction list (date, ticker, type, amount, disclosure date)
- **AI Insights tab**: Derived observations from the trading data such as concentration, recurring themes, sector bias, turnover, conviction names, and unusual changes between quarters. This should be heuristic/generated from available data, not an LLM-dependent feature.
- **Portfolio Structure tab**: Sector allocation, ticker concentration, and quarter-over-quarter composition shifts using treemap/stacked bars inspired by the screenshots
- **Performance History tab**: Estimated PnL/performance history using D3 area/line chart computing portfolio performance from all trades + current prices using `MarketServiceClient.listMarketQuotes` and `fetchHistoricalPrices`; include summary cards for return, drawdown, and win/loss bias where feasible
- **Filings / Disclosures tab**: Raw congressional disclosures/source records, grouped by filing or disclosure date, with links or source metadata where available

### 5. NEW: `src/components/entity-detail/renderers/institution.ts`

New `InstitutionRenderer` class implementing `EntityRenderer`:

**Data interface:**
```ts
interface InstitutionData {
  name: string;
  cik: string;
}
```

**Enriched data interface:**
```ts
interface InstitutionEnriched {
  name: string;
  cik: string;
  holdings: InstitutionalHolding[];
  totalHoldings: number;
  totalValue: number;
  filingDate: string;
  topHoldings: InstitutionalHolding[];  // top 10
  sectorBreakdown: SectorAllocation[];
  wikiSummary?: string;
  wikiUrl?: string;
}

interface SectorAllocation {
  sector: string;
  count: number;
  value: number;
  percentage: number;
}
```

**`renderSkeleton()`**: Header with institution name, CIK badge, loading placeholders.

**`enrich()`**:
- Fetch holdings via `fetchInstitutionalHoldings(cik)`
- Compute sector breakdown (group by first 2 chars of CUSIP or by issuer name heuristics)
- Hero image via Wikipedia

**`renderEnriched()`**: Render tabs: **Top Holdings** | **Largest Trades** | **AI Insights** | **Portfolio Structure** | **Performance History** | **Filings / Disclosures**

- **Top Holdings tab**: Hero/header plus top holdings table, treemap-style holdings map, concentration stats, AUM, # holdings, filing date, ranked top 10/top 50 view
- **Largest Trades tab**: Largest new buys, largest sells, and biggest position changes between filings. Since only a single filing snapshot is currently available per CIK, this tab will use quarter-over-quarter deltas only when prior filings can be inferred/fetched; otherwise it will gracefully fall back to the largest positions and latest changes available from the current dataset.
- **AI Insights tab**: Heuristic insights such as concentration risk, sector tilt, new conviction names, reduced exposure, international vs domestic mix, and notable themes inferred from issuer names/CUSIP mapping
- **Portfolio Structure tab**: Sector allocation over time when prior filings are available, otherwise current sector treemap plus allocation bars. Use visuals inspired by the screenshots: stacked sector bars and treemap blocks.
- **Performance History tab**: Estimated portfolio performance history based on the institution's current holdings and historical prices. This is an approximation of manager-weighted portfolio return, clearly labeled as estimated because it is built from filing snapshots rather than exact trade timestamps.
- **AUM tab**: Institution AUM-focused page modeled on the screenshot. Include reported AUM summary card/table, discretionary vs non-discretionary AUM if available, reporting date, and composition charts such as US vs foreign investors, fund owners vs other investors, and client-type split. If only partial AUM data is available from our sources, render the tab with graceful placeholders and source labeling rather than omitting it.
- **Filings / Disclosures tab**: 13F filing metadata, SEC/EDGAR links, filing types, and any associated source records

## Data Flow

### Politician Click Flow
```
User clicks politician name in Congress tab
  → PortfolioPanel dispatches wm:open-entity-detail event
    → EntityDetailPanel.show('congressPolitician', { name, party, chamber, district, state })
      → CongressPoliticianRenderer.renderSkeleton() — immediate
      → resolveEntityHeroImage() — fetches Wikipedia image async
      → CongressPoliticianRenderer.enrich() — fetches all trades, filters by name, aggregates positions,
          fetches current quotes via MarketServiceClient, fetches historical prices via fetchHistoricalPrices
      → CongressPoliticianRenderer.renderEnriched() — renders full profile with estimated PnL chart
```

### Institution Click Flow
```
User clicks filing row or notable investor card
  → PortfolioPanel dispatches wm:open-entity-detail event
    → EntityDetailPanel.show('institution', { name, cik })
      → InstitutionRenderer.renderSkeleton() — immediate
      → resolveEntityHeroImage() — fetches Wikipedia image async
      → InstitutionRenderer.enrich() — calls fetchInstitutionalHoldings(cik)
      → InstitutionRenderer.renderEnriched() — renders full profile
```

## Design Notes

- The politician and institution profile pages should borrow the interaction model from `CompanyRenderer`, but visually mirror the portfolio reference tabs you shared rather than a generic overview/financials layout
- For the estimated PnL chart on the politician profile, we'll use D3 (already a project dependency) — combine the politician's trade history with current market quotes from `MarketServiceClient.listMarketQuotes` to estimate a portfolio value over time, similar to the visualizer's `drawPerformanceChart` but adapted for politician trading activity
- The quarterly PnL estimation works by: aggregating all buys/sells per ticker to estimate position sizes, then using `fetchHistoricalPrices` to compute past portfolio values, producing an area chart showing estimated portfolio performance
- The existing `EntityDetailPanel` maximize feature allows users to expand to full-screen view, which will be useful for detailed holdings tables
- Politician trades are filtered client-side from the existing `fetchCongressTrades()` endpoint — no new API needed
- Institutional holdings use the existing `fetchInstitutionalHoldings(cik)` endpoint
- Sector allocation for institutions will use a heuristic: group by first CUSIP characters or issuer name keywords, since we don't have a separate sector classification API
- `AI Insights` should be deterministic and generated from the data already loaded into the panel, for example: top concentration, strongest adds/reductions, sector imbalance, turnover, and notable single-name exposure
- `Performance History` for institutions must be explicitly labeled as estimated because 13F data is delayed and filing-based; avoid implying exact manager returns
- `Largest Trades` for institutions may need a staged implementation: first ship current-position ranking and latest-change views, then enrich with quarter-over-quarter deltas if prior filings are available from the SEC feed or another existing source
- `Filings / Disclosures` should use the document-style tab the user requested and become the place for SEC/EDGAR/source references rather than leaving those links scattered across other tabs
- `AUM` should be institution-only and should clearly separate `13F AUM` from any broader `reported adviser AUM` if both are available; do not conflate them
- If the codebase lacks a true adviser-AUM source, the initial AUM tab should still ship with filing-based summary metrics and explicit source/explanation copy so the UI structure is in place without overstating data fidelity
