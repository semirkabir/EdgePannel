# Fix: Institutions Filing Click + Congress Politician Click → Entity Detail Panel

## Root Cause

**Filing rows don't open the detail panel** because SEC 13F Atom feed CIK extraction fails for every entry:

- `<id>` is URN format: `urn:tag:sec.gov,2008:accession-number=0002085853-26-000447` → `extractCikFromId(/CIK=(\d+)/i)` never matches
- `<summary>` is HTML with Filed/AccNo/Size → `extractCikFromSummary(/CIK[:\s]*(\d+)/i)` never matches
- Result: `entry.cik = ''` → `if (cik)` at PortfolioPanel line 420 silently skips the dispatch

The CIK **is** available in two places per entry:
1. `<title>`: `13F-HR - Crown Wealth Group, LLC (0001845698) (Filer)` → CIK in trailing parentheses
2. `<link href>`: `https://www.sec.gov/Archives/edgar/data/1845698/...` → CIK in path segment after `/data/`

Congress politician names also lack visual click affordance and the `.pf-cg-name` click handler has no fallback when cache match fails.

## Changes

### 1. Fix CIK extraction in `sec-filings.ts`

**File:** `src/services/market/sec-filings.ts`

- Add `extractCikFromTitle(title)` — extracts trailing `(\d{6,10})` parenthesized CIK from the title string (like `13F-HR - Crown Wealth Group, LLC (0001845698) (Filer)`)
- Add `extractCikFromLink(link)` — extracts CIK from the URL path pattern `/data/(\d{6,10})/`
- Update the extraction chain in `fetchSec13FFeed()` to:
  ```
  let cik = extractCikFromId(id);
  if (!cik) cik = extractCikFromLink(link);
  if (!cik) cik = extractCikFromTitle(title);
  if (!cik) cik = extractCikFromSummary(summary);
  ```
  Link extraction should be tried before title because the link CIK is un-padded (no leading zeros), and the title CIK may be zero-padded — both represent the same entity.

Also strip leading zeros from CIK for API consistency (the `/api/portfolio-data` endpoint handles CIK zero-padding). Use a helper `normalizeCik(cik)` that strips leading zeros, or keep them as-is since `handle13FHoldings` already pads with `.padStart(10, '0')`.

### 2. Fix filing row click guard in `PortfolioPanel.ts`

**File:** `src/components/PortfolioPanel.ts`

- Replace `if (cik)` guard with behavior that still opens the panel when CIK is missing. Two options:
  - **Preferred:** Always dispatch `wm:open-entity-detail` with whatever data is available. If CIK is empty, the `InstitutionRenderer.enrich()` will try to fetch holdings with an empty CIK and show an error — but at least the panel opens and shows the name. The renderer should handle the error gracefully.
  - **Alternative:** Show a visual indicator (e.g., grey out the row, `cursor: default`) when CIK is empty, and don't dispatch.

Go with the preferred approach: always dispatch. In `InstitutionRenderer.enrich()`, handle the case where `cik` is empty by showing a "No CIK available" message instead of crashing.

### 3. Make congress politician names visually clickable

**File:** `src/components/PortfolioPanel.ts`

- Add `cursor: pointer` styling to `.pf-cg-name` — add to `portfolio-panel.css`:
  ```css
  .pf-cg-name { cursor: pointer; }
  .pf-cg-name:hover { text-decoration: underline; }
  ```
- Also make `pf-filing-row` have `cursor: pointer` (it already has `cursor: pointer` in the existing CSS — verify).

### 4. Add graceful CIK-empty handling in `InstitutionRenderer`

**File:** `src/components/entity-detail/renderers/institution.ts`

- In `enrich()`, if `d.cik` is empty/falsy, return enriched data with empty holdings and a note explaining that CIK is required to fetch holdings.
- In `renderSkeleton()`, always show the name even if CIK is absent.
- In the holdings tab, if CIK is missing, show a callout explaining that the institution couldn't be looked up without a CIK and provide a link to search EDGAR.

### 5. Congress tab — equivalent of "click opens detail panel"

Already implemented in the previous session (`.pf-cg-name` click handler dispatches `wm:open-entity-detail` with type `congressPolitician`). The main gap is:
- Visual affordance (cursor/hover style on `.pf-cg-name`)
- Graceful handling when `this.congressCache?.find()` fails to match the name text

Neither is a blocking bug — the click handler works for matched names. Adding the CSS cursor style (step 3 above) addresses the visual issue.
