# Design Sync Notes — World Monitor

## Repo shape

Off-script layout: this is a Vite web app, not a standalone npm package. The `ds-bundle/` directory is **hand-crafted** — `_ds_bundle.js` is a hand-written IIFE using `window.React` / `window.ReactDOM`, and preview cards are pure HTML/CSS (no React). The converter's standard `package-build.mjs` path does not apply. On re-sync, skip the build step entirely and go straight to validate.

## Re-sync recipe

```sh
SKILL_DIR="<path to skill>"
cp -r "$SKILL_DIR"/{package-validate.mjs,package-capture.mjs,resync.mjs,lib,storybook} .ds-sync/
echo '{"name":"ds-sync-deps","private":true}' > .ds-sync/package.json
(cd .ds-sync && npm i esbuild ts-morph @types/react)

# Regenerate _ds_bundle.js header after any bundle edits:
node /tmp/stamp-bundle-header.mjs   # see .design-sync/stamp-bundle-header.mjs

# Regenerate _ds_sync.json after bundle/preview changes:
node /tmp/gen-sync-json.mjs         # see .design-sync/gen-sync-json.mjs

# Validate:
LD_LIBRARY_PATH=/tmp/libnspr4-extract/usr/lib/x86_64-linux-gnu:/tmp/chrome-libs-extract/usr/lib/x86_64-linux-gnu \
  node .ds-sync/package-validate.mjs ./ds-bundle
```

The `LD_LIBRARY_PATH` workaround is needed in WSL2 because `playwright install-deps` requires sudo and system libnspr4/libnss3 may be missing. Packages were downloaded via `apt-get download` and extracted manually. On a fresh machine, try `sudo npx playwright install-deps chromium` first.

## Component naming

- The component folder was `NotifDropdown` but the bundle export was `NotifBell`. Renamed to `NotifBell` on 2026-06-17 to match the bundle. If you add new components, ensure the folder name EXACTLY matches the export name in `window.WorldMonitor`.

## `_vendor/` directory

Added in the 2026-06-17 sync to make the validator's bundle-export smoke check work. Generated by `vendorReact()` from `lib/emit.mjs` using the repo's node_modules (React 19 — built via esbuild since React 19 has no UMD builds). The preview cards are pure HTML/CSS so they don't load `_vendor/`, but the design agent's bundle smoke check needs it.

## Font handling

The CSS uses `--font-mono`/`--font-body` stacks with system font fallbacks (SF Mono, Monaco, Cascadia Code, Fira Code, Inter). No `@font-face` rules → no font files shipped. The original sync uploaded TTF files but they're now orphaned and were deleted. `runtimeFontPrefixes` suppresses `[FONT_MISSING]` in validation. If brand fonts need to ship in the future, add `@font-face` rules to `_ds_bundle.css` and copy the woff2/ttf files to `ds-bundle/fonts/`.

## Preview card structure

All 23 preview cards are pure HTML/CSS — they use CSS classes directly (`.wm-panel`, `.filter-btn`, etc.) rather than rendering via the React bundle. This means:
- `_preview/` directory is NOT used (no compiled story JS)
- No `.jsx` or `.tsx` stub files needed
- The render check screenshots the HTML directly without evaluating the React components

## Re-sync risks

- **Bundle/folder name drift**: If the bundle (line 200+: `window.WorldMonitor = {...}`) adds/renames exports, the corresponding component folder must also be renamed AND the bundle header must be re-stamped. Nothing catches this automatically.
- **Header must be kept fresh**: `_ds_bundle.js` first line must match the actual component list. After any edit to the bundle or component folders, re-run `stamp-bundle-header.mjs` and `gen-sync-json.mjs`.
- **LD_LIBRARY_PATH not permanent**: The extracted shared libs at `/tmp/libnspr4-extract/` and `/tmp/chrome-libs-extract/` are in `/tmp` and may be wiped. Re-extract on a fresh machine with: `apt-get download libnspr4 libnss3 libdrm2 ...` then `dpkg-deb -x`.
- **React 19 vendor bundle**: `_vendor/react.js` is an esbuild-bundled React 19 IIFE. If React is upgraded, re-run `vendorReact()` from `lib/emit.mjs`.
- **No source tracking**: Since there's no standard package build, `sourceKeys` in `_ds_sync.json` track `.design-sync/previews/` files (none authored) and config. Any edit to the HTML previews or bundle requires a manual re-generate of `_ds_sync.json`.
